# Proposal integrity repairs — 25 September 2026

This bounded repair implements the existing non-negotiable invariants in the
decision register: actual-submitter separation, complete scope membership and
no false aggregate completion. It does not settle the remaining contract or
pilot decisions and does not release the live workspace adapter.

- Manual publication and scheduled dispatch require a successful, uniquely
  matched Catalog result with a price record for every requested line. A
  rejected, absent, duplicate or mismatched result cannot create a published
  transition or completion event. Catalog operation evidence remains the
  source for reconciliation; some rows may already have changed.
- Approval reads immutable submission evidence under a proposal row lock in
  the decision transaction. The actual submitter cannot approve even when
  another actor created the proposal. Missing evidence blocks approval.
- Scope building and preview follow all Catalog pages, batch price reads and
  reject unresolved or ambiguous current prices before creating a preview.
  The current response contract cannot represent unresolved rows; this repair
  reports a failed precondition instead of silently omitting them. A richer
  per-row resolution contract remains work for the accepted delivery plan.

Local validation: 79 Proposal unit tests and seven BuildScope handler tests
passed; runtime, unit-test and integration-test TypeScript checks passed.
The real Postgres integration suites require Docker and must run in CI.

Deployment investigation found that Proposal's Dockerfile is still a stub.
Cloudflare's configured frontend builds serve the sample workspace, not this
service. Passing a frontend build does not deploy or verify these backend
repairs. Production release needs a real Proposal image and service wiring.

Remaining PRD work includes Initiative persistence, controlled-version versus
concurrency contracts, all-applicable guardrails, tax/cost basis and margin
exposure, scoped authorisation, per-row execution/retry evidence, notifications
and the verified live adapter. These repairs are not full R1 acceptance.
